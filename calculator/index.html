    How it works

    02

    nternet-Link is OtterCad's project. OtterCad started it, built the hardware and wrote the build guides. I wrote the software for V3, the camera version.

    V1 · Ti-GPTInside the case

    A chip inside the calculator

    An ESP32-C3 and a CP2102 USB-to-serial board go inside the case, soldered to the calculator's USB lines, with switches for power and host mode. You type a question and it asks ChatGPT. Opening the case is a big ask, so this one is kept as a reference.

    By OtterCad

    V2 · nternet-LinkPlug-in

    A plug-in adapter

    Everything moves outside. A XIAO ESP32-C3 and a CP2102 sit in a 3D-printed case that plugs into the USB mini port, so there's no mod. Its demos are a serial echo test and a ChatGPT chat app.

    By OtterCad · Demo video ↗

    V3 · CameraNow

    A camera that solves

    A XIAO ESP32-S3 with an OV5640 autofocus camera. Snap a handwritten problem, get the steps. LoRa radio, for calculator-to-calculator messages without Wi-Fi, is in the works too.

    Hardware by OtterCad · Software by me

    My part: the V3 software

    C++ · ESP32-S3 · 752 lines

    The firmware

    Camera setup and autofocus, the serial protocol, Wi-Fi setup driven from the calculator, and the calls to Groq. It also serves a small web page with a live camera view, so you can aim it from any browser on the same Wi-Fi.

    Lua · TI-Nspire · 1,314 lines

    The calculator app

    Finds the adapter over serial, sends commands, shows progress, then wraps and scrolls the answer. Press T to type a question instead, with Tab to autocomplete ML terms. Wi-Fi setup happens on the calculator too.

    Python · Flask · 138 lines

    The local proxy

    A small server for my Mac with the same two calls: /vision for photos and /ask for typed questions. The Groq key stays in a file on the laptop instead of in the firmware. An install script starts it at login, keeps the Mac awake while it's plugged in, and announces it on the network with mDNS. The firmware in the repo still calls Groq directly.

    My pull request #4, “Add V3 camera software stack”, was merged in February 2026. In August I added the proxy and more updates to the firmware and the app.

    Each answer can run up to 4,096 tokens. A request gives up after 30 seconds.

    Not for tests

    The repo is clear about this and so am I. It's a learning project about serial links, embedded networking and APIs. Please don't bring it into an exam.

    All 11 serial commands +
    Calculator sendsESP32-S3 answers
    PINGPONG
    SNAPOK:PROCESSING, then LEN:, RESULT: and >>>END<<< (photo to answer)
    ASK:questionSame as SNAP (typed question to answer)
    FOCUSOK:FOCUSED or ERR:FOCUS_FAILED
    SCANOK:SCANNING, then NETWORKS: (up to 10 names with signal strength)
    WIFI:name:passwordOK:CONNECTING, then WIFI:OK:address or WIFI:FAIL
    IPIP:address or IP:NOT_CONNECTED
    CLEAROK:CLEARED (forgets the chat history)
    RESETOK:RESET (clears the busy flag)
    RESTARTOK:RESTARTED (soft restart)
    HARDRESETOK:REBOOTING (full reboot)

    While it's busy, SNAP and ASK get ERR:BUSY. If a job runs past 2 minutes, a watchdog sends ERR:TIMEOUT. On boot the chip says WIFI:NONE, then READY.
